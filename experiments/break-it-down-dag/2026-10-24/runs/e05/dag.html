Evaluation prerequisites

An arrow A → B means understanding B requires A. The initial graph and research history are preserved in dag.json.

Why each dependency exists

  • program → variation: Must distinguish program execution from correct behavior.
  • goal → case: Expected behavior determines what context and checks a case needs.
  • case → grader: A grader needs an explicit input and expected behavior.
  • grader → sample: Aggregate scores only mean something once individual judgments are defined.
  • sample → compare: Comparisons require understanding finite and variable observations.
  • compare → workflow: Release decisions require comparable evidence.
  • case → workflow: Implementation needs concrete case records.
  • goal → outcome: Knowing success criteria explains why both final effect and required permission matter.
  • outcome → grader: Checks must target correct observables.
  • population → sample: Generalization depends on how the sample relates to future traffic.
  • variation → sample: Repeated executions can disagree even on one case.
