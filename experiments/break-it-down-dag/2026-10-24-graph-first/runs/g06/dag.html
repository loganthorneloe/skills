    activation — Why put a nonlinear operation between weighted sums, and what does ReLU calculate?

    supported

    Weighted sums alone compose into another weighted sum. An activation can change that form. ReLU(z)=max(0,z): it returns 0 when z is negative and z otherwise. We use this simple nonlinear operation for the hidden value; outputs remain weighted values.

    loss — How is a prediction mismatch turned into one number to reduce?

    supported

    Given desired outputs y1,y2, choose L=((p1-y1)^2+(p2-y2)^2)/2. Squaring makes either error direction costly; summing combines outputs. The factor 1/2 is a declared example convention. Across training examples, average their losses.

    sensitivity — What does sensitivity mean without assuming calculus?

    supported

    For a very small change delta in one number, the resulting change in another is approximately sensitivity times delta. Sign indicates increase or decrease; magnitude gives the scale near the present values. A derivative is this limiting change ratio, not the historical share of blame for an existing error.

    local_rules — How do addition, multiplication, squaring, and ReLU respond to tiny changes?

    supported

    For a+b, each input has local sensitivity 1. For a*b, changing a while b stays fixed has sensitivity b, and vice versa. For e squared, (e+delta)^2-e^2=2*e*delta+delta^2; dividing by delta gives 2*e+delta, tending to 2*e as delta shrinks. Thus 0.5*(p-y)^2 has sensitivity p-y to p when y is fixed. ReLU has sensitivity 1 at positive inputs and 0 at negative inputs because its output respectively copies the input or remains zero. At zero the two sides disagree; a program needs a convention.

    chain — How does a small effect pass through successive calculations?

    supported

    If an early change is multiplied by local factor a in one operation and then factor b in another, the resulting change is approximately ab times the original change. Multiply these local factors through a path: this is the chain rule.

    reverse — Why work backward, and what must be saved?

    supported

    Save intermediate values while predicting. Set loss sensitivity to itself to 1. Visit operations from the loss backward: multiply each incoming sensitivity by the operation’s local factor and add contributions at shared values. This reuses each downstream result instead of tracing every parameter-to-loss path separately.

    gradient — What information does the completed backward pass provide?

    supported

    The parameter gradient is the collection of sensitivities of the chosen scalar loss to each weight and bias, holding other parameters fixed at current values. It describes local change, not a unique decomposition of the existing loss.

    update — How are these sensitivities used to learn?

    supported

    For each parameter theta, choose a small positive step size eta and set theta_new=theta-eta*gradient_theta. Locally, the predicted loss change is -eta times the sum of squared parameter sensitivities, so a nonzero gradient gives a decrease for a sufficiently small step where the loss is differentiable. Repeat new forward and backward passes. Backprop computes the gradient; the update is a separate optimization choice.

    limits — Why can a gradient-based adjustment fail to lower the desired error?

    supported

    A finite update can depart from the tiny-change prediction; choose a step size and recompute the loss. At ReLU zero, left and right sensitivities differ, so no ordinary derivative exists; a program can choose zero as its backward convention. Our example stays strictly positive. Examples may favor conflicting changes: average their gradients for an average training loss, or estimate this with a batch. The single-example calculation below establishes only its own loss change.

    trace_backward — What numerical sensitivity does each parameter receive?

    supported

    Write dL/du for the sensitivity of loss L to u; this is one notation label, not a division to compute. Start with dL/dL=1. Each half-squared error gives dL/dp1=p1-y1=1 and dL/dp2=p2-y2=-1. For p1=v1*h and p2=v2*h, dL/dv1=1*h=2 and dL/dv2=(-1)*h=-2. Both uses of h contribute: dL/dh=1*v1+(-1)*v2=1-0.5=0.5. Since z=w*x+b=2>0, ReLU passes factor 1, giving dL/dz=0.5. Finally dL/dw=0.5*x=1 and dL/db=0.5*1=0.5. The shared hidden value receives opposing contributions, combined before passing backward.

    trace_update — Does a small simultaneous update actually reduce this example loss?

    supported

    Use the old gradients for every update, with eta=0.1: w=1-0.1*1=0.9; b=0-0.1*0.5=-0.05; v1=1-0.1*2=0.8; v2=0.5-0.1*(-2)=0.7. New h=max(0,0.9*2-0.05)=1.75. New p1=0.8*1.75=1.4 and p2=0.7*1.75=1.225. New L=((1.4-1)^2+(1.225-2)^2)/2=(0.16+0.600625)/2=0.3803125, below 1. The local approximation predicts change -0.1*(1^2+0.5^2+2^2+(-2)^2)=-0.925, while actual change is -0.6196875. Finite simultaneous updates need a new forward calculation.

    target — How does a tiny network work out each weight’s influence on prediction error and use that information to learn?

    supported

    A network does not assign a historical fraction of prediction error to each weight. Backpropagation computes how a tiny change to each weight or bias would change a chosen scalar loss at the current settings. It evaluates the network, saves values, then multiplies local sensitivities backward and adds contributions from shared paths. The gradient collects these results. A separate rule subtracts a small multiple of each gradient component from its parameter, followed by a new forward pass. In the constructed two-output example the gradient in (w,b,v1,v2) order is (1,0.5,2,-2), and a step of 0.1 lowers loss from 1 to 0.3803125. Repeating on training examples can reduce their average loss; neither the gradient nor this example supplies a global success guarantee.
