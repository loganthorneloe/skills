Attention in transformer language models.

The answer

Attention lets every word in a passage pull in information from the other words, in proportions the model computes on the fly. For each position it scores how well that position's "query" vector matches every other position's "key" vector, turns the scores into weights that sum to 1, and outputs a weighted average of the other positions' "value" vectors. The whole operation is a few matrix multiplications.

That last fact is why it mattered. Earlier language models read text one word at a time, so training could not be split across the many arithmetic units of a GPU, and information from far back in a passage had to survive many steps to be used. Attention connects any two positions in one step and computes all positions at once. That made it practical to train much larger models on far more text, and the 2020 measurements below show such models getting steadily better as they grew. ChatGPT is a model in that line, a large GPT model fine-tuned for conversation.

What a language model is doing

A language model is a program trained to predict the next piece of text. Text is first split into tokens, which are words or word fragments drawn from a fixed vocabulary; the tokenizer in OpenAI's 2020 scaling study has 50,257. Each token is looked up in a table that maps it to a list of numbers, a vector called an embedding. A short passage therefore becomes a matrix with one row per token.

The model then transforms that matrix through a stack of layers and, at the end, turns the last row into a probability for every token in the vocabulary. Training shows the model billions of passages, compares its predicted probabilities with the token that actually came next, and nudges every number in the model (its parameters, also called weights) in the direction that would have made the right token more likely. That nudging, computed by calculus over the whole program, is gradient descent. Nobody writes rules into the model; the useful behaviour has to emerge from those adjustments.

The difficulty is that predicting the next token often depends on tokens far back. In "The cat that the dog chased all afternoon finally sat down because it was tired," the word it refers to cat, eleven words earlier. A layer that only transforms each row on its own cannot use that. Something has to move information between rows. Attention is that something.

What attention computes

Attention starts from three matrices made from the same input. Multiply the token matrix X by three learned weight matrices and you get Q = XWQ, K = XWK and V = XWV. Each token now has a query vector, a key vector and a value vector. The names describe their roles. A token's query is compared against every token's key; the better the match, the more of that token's value it receives. The paper defines it in one line:

"The output is computed as a weighted sum of the values, where the weight assigned to each value is computed by a compatibility function of the query with the corresponding key." (Vaswani and colleagues, §3.2)

For all tokens at once, the computation is

Attention(Q, K, V) = softmax( QKT / √dk ) V

Read it from the inside out. QKT is an n×n matrix whose entry (i, j) is the dot product of token i's query with token j's key, one score for every pair of tokens. Dividing by √dk, the square root of the key length, keeps the scores from growing just because the vectors are long. Softmax then works on each row separately. It exponentiates every score and divides by the row's total, so the row becomes positive weights that sum to 1 and large scores dominate. Multiplying those weights by V gives each token a new vector that is a blend of the value vectors it attended to.

The left diagram shows how little machinery is involved: two matrix multiplications with a scale, a mask and a softmax between them. Nothing here is specific to language. What makes it useful is that WQ, WK and WV are learned. Gradient descent adjusts them so that the queries and keys of tokens that ought to share information end up pointing in similar directions.

The paper gives a short reason for the √dk. If the query and key entries are independent with mean 0 and variance 1, their dot product has variance dk. With 64-number keys the raw scores would spread eight times wider than with 1-number keys, and softmax would put almost all weight on one token. The authors suspect that this pushes softmax "into regions where it has extremely small gradients," meaning training would barely adjust it. They offer this as a suspicion supported by the variance argument, not as a tested result.

One more rule for text generators: no looking ahead

A model trained to predict the next token must not see that token. GPT-style models enforce this with a causal mask. Before softmax, every score where token i would look at a later token j is set to −∞. Since e−∞ = 0, those weights become exactly zero, and each token can only blend information from itself and earlier tokens. In the paper's words, the decoder works "by masking out (setting to −∞) all values in the input of the softmax which correspond to illegal connections." The mask also means that one pass over a training passage of n tokens produces n next-token predictions at once, one per position, each using only what came before it.

Try three things. With it selected, about 62% of the weight lands on cat, because those two vectors point the same way, so the output vector is mostly cat's value. That output is how information about the cat reaches the position of it. Select cat with the mask on and only The and cat get any weight; turn the mask off and the later tokens join in, which is what a text generator must not allow. Turn off the scaling and the weights become more lopsided, a small version of the effect √dk is there to limit.

Many heads, many layers

One attention computation can only produce one blend per token, but a token often needs several kinds of information at once: what a pronoun refers to, which verb a noun belongs to, what the previous word was. The Transformer therefore runs several attention computations side by side, called heads, each with its own WQ, WK and WV. Their outputs are joined end to end and multiplied by one more learned matrix (the right half of Figure 2). The original model used 8 heads with 64-number keys; GPT-3's largest model uses 96 heads with 128-number keys in each of its 96 layers (Brown and colleagues, Table 2.1). In the original paper, cutting to a single head lowered translation quality by 0.9 BLEU points against the best setting, a modest but real loss.

Each layer pairs attention with a small feed-forward network applied to every token separately, and layers are stacked. Later layers attend over vectors that already contain information gathered by earlier layers, so the model can build up combinations step by step.

Attention has a blind spot that the design has to patch. The weighted sum gives the same result if you shuffle the tokens, because nothing in QKT knows which row came first. The Transformer adds a positional encoding, a vector that depends on the token's position, to each embedding before the first layer, so that word order can affect queries and keys.

What do trained heads actually do? The original paper printed examples from its translation model.

Follow the lines out of making. Several heads, shown in different colours, put their weight on more and difficult, six and seven tokens later, which completes the phrase "making … more difficult." A recurrent model would have had to carry that link through six sequential updates; here it is one weighted sum. The limit is that the authors picked this sentence, and it comes from a translation model that can see the whole sentence rather than a GPT-style model.

A more systematic study found a specific two-head pattern in GPT-style models. Olsson and colleagues describe induction heads, which look back for an earlier occurrence of the current token and copy whatever followed it, completing a pattern [A][B] … [A] with [B]. Given "The cat sat on the mat. The cat …," induction heads "will promote the continuation 'sat on the mat'." The authors connect these heads to in-context learning, a model's ability to pick up a pattern from examples in its prompt without any retraining, the ability GPT-3 showed on few-shot tasks. In small models, switching the heads off greatly reduced in-context learning; for large models the authors call their evidence indirect.

These pictures need care. Jain and Wallace found that in the recurrent classifiers they tested, attention weights were "frequently uncorrelated with gradient-based measures of feature importance," and that very different weight patterns could produce the same prediction. An attention map shows where information was drawn from, not proof of why the model produced its answer.

Why attention made models like ChatGPT possible

Before 2017 the best language models were recurrent neural networks, usually a kind called LSTM. A recurrent network keeps one running vector and updates it token by token: the state after token t is a function of the state after token t−1 and token t. Vaswani and colleagues spell out the cost: "This inherently sequential nature precludes parallelization within training examples, which becomes critical at longer sequence lengths." A GPU is fast because it does thousands of multiplications at the same time, and a loop where each step waits for the previous one leaves most of it idle.

Compare the first two rows. A recurrent layer needs n sequential operations for n tokens, while self-attention needs a constant number no matter how long the text is. The last column says the same thing about information. In a recurrent layer, a signal from the first token must pass through up to n updates to reach the last one, and long chains are hard to train. In self-attention every token is one step from every other. The table is a mathematical estimate rather than a stopwatch measurement, but the paper's own training times bear it out: its base translation model beat earlier published results after 12 hours on 8 GPUs. Attention is also cheap per operation because, as the authors note, dot-product attention "can be implemented using highly optimized matrix multiplication code," the operation GPUs are designed for.

Faster training would matter less if transformers did no better with the extra scale. Kaplan and colleagues at OpenAI trained transformers and LSTMs on the same web text with the same 1,024-token context and compared them.

In the left panel the transformer line sits below every LSTM line at every size, and the gap widens as models grow. The right panel explains why. For the first few tokens of a passage the two kinds of model predict equally well, but LSTM loss stops falling after fewer than 100 tokens, while transformer loss keeps falling all the way to token 1,000. A transformer keeps using text far back in its context, because attention reaches it in one step. The limits are that these models reach about a billion parameters, far smaller than GPT-3, and loss measures prediction error, not how helpful a chatbot is.

The same paper found that transformer loss improves in a predictable way: "The loss scales as a power-law with model size, dataset size, and the amount of compute used for training, with some trends spanning more than seven orders of magnitude." A predictable curve means the gain from a bigger model can be estimated before paying to train it. Later work by Hoffmann and colleagues revised the best split between model size and training data, concluding they "should be scaled equally."

GPT-3, published a few months later, applied this at scale. It is "an autoregressive language model with 175 billion parameters," built from the same transformer design as GPT-2 with alternating full and locally restricted attention patterns, and it could do tasks from a few examples written into the prompt. ChatGPT came next. OpenAI's announcement says that "ChatGPT is fine-tuned from a model in the GPT-3.5 series, which finished training in early 2022," using human-written example conversations and then reinforcement learning from human feedback, in which people ranked model replies and the model was trained to produce higher-ranked ones. OpenAI has not published GPT-3.5's architecture, so its transformer design is an inference from the series name and the GPT-3 paper rather than a published fact.

So attention did not make ChatGPT by itself. Huge datasets, GPU clusters and the conversational fine-tuning were all needed. What attention supplied was an architecture that could absorb all of that compute in parallel, use long stretches of text, and get reliably better as it grew.

What attention costs and what it does not explain

The n2 in the first cell of Table 1 is attention's price. Every token is scored against every other, so doubling the length of a passage quadruples the size of the score matrix. This is a large part of why long contexts are expensive to run. GPT-3's sparse layers and the paper's "restricted" row are both ways of scoring only some pairs to cut that cost.

Attention is also only part of each layer. In the standard sizing Kaplan and colleagues describe, the feed-forward networks hold two thirds of each layer's parameters and attention one third. Attention decides which earlier tokens feed into each position; it does not by itself account for what the model does with that information.
