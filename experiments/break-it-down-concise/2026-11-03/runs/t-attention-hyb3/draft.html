How attention works in language models.

The short answer

Attention lets every word in a text pull in information from every other word in one step. For each position, the model scores how relevant every other position is, using dot products between learned vectors, turns those scores into weights that sum to one, and takes the weighted average of what those positions offer. The whole computation is matrix multiplications plus one softmax.

It made ChatGPT possible less by being clever than by being trainable. Earlier models read text one word at a time, so training could not be spread across a sequence, and information from far back had to survive a long chain of steps. Attention does the whole sequence at once with matrix multiplications that graphics processors run well, and it connects any two words directly. That let researchers train much larger models on much more text, and those models kept getting better as they grew. ChatGPT is one of those models, then further trained on human feedback to follow instructions.

What a language model is doing

A language model predicts the next piece of text. The text is first split into tokens, which are words or word fragments, and each token is replaced by a list of numbers called an embedding. In the original Transformer each embedding has 512 numbers; in GPT-3 it has 12,288. The embeddings are not designed by hand: they start random and are adjusted during training, as are all the other matrices described below.

Training means repeatedly showing the model real text, measuring how much probability it gave to the token that actually came next, and nudging every number in the model to make that probability higher. The nudge for each number is computed from the derivative of the error with respect to that number, its gradient. A design is practical only if those gradients are informative and cheap to compute at scale.

The hard part is context. The word "bank" needs a different vector in "river bank" than in "bank loan", and a pronoun needs information about a noun that may be many sentences back. A model needs some way for each token's vector to absorb information from the others. Attention is that way.

What attention computes

Start with the embeddings stacked as rows of a matrix X, one row per token. Attention multiplies X by three learned matrices to get three new matrices with one row per token:

  • the query row q, which describes what this token is looking for;
  • the key row k, which describes what this token can be matched on;
  • the value row v, which is the information this token hands over when it is chosen.

Those descriptions are roles, not built-in meanings; training decides what the numbers come to encode. The relevance of token j to token i is the dot product of i's query with j's key. A softmax turns each row of scores into positive weights that sum to one, by exponentiating each score and dividing by the row's total. Token i's output is then the weighted sum of all the value rows. The paper puts it in one line: "The output is computed as a weighted sum of the values, where the weight assigned to each value is computed by a compatibility function of the query with the corresponding key." For a whole sequence at once:

Attention(Q, K, V) = softmax( Q·Kᵀ / √dk ) · V

Here dk is the length of each query and key row. The figure below is the same equation drawn as a pipeline, read from the bottom.

A worked example with three tokens

Suppose the text is "the dog barked" and each token has a two-number embedding: the = [1, 0], dog = [0, 1], barked = [1, 1]. Pick small weight matrices, as training might have left them:

WQ = [[1, 0], [1, 2]]

Queries Q = X·WQ: the [1, 0], dog [1, 2], barked [2, 2].

WK = [[2, 0], [0, 1]]

Keys K = X·WK: the [2, 0], dog [0, 1], barked [2, 1].

WV = [[1, 0], [0, 3]]

Values V = X·WV: the [1, 0], dog [0, 3], barked [1, 3].

Follow "barked". Its query [2, 2] dotted with the three keys gives 4, 2, and 6. Dividing by √2 gives 2.83, 1.41, and 4.24. A language model must not look at tokens that come later, so for "the" and "dog" the scores against later tokens are replaced with minus infinity, which the softmax turns into a weight of exactly zero. "Barked" is last, so it keeps all three scores.

The softmax of 2.83, 1.41, 4.24 is 0.187, 0.045, 0.768, so "barked" builds its new vector as 0.187 × [1, 0] + 0.045 × [0, 3] + 0.768 × [1, 3] = [0.96, 2.44]. That new vector is the token's representation after one attention step, now mixed with context. Nothing here is specific to language: it is a lookup where every query matches every key a little, and the result is a blend of values in proportion to how well they matched. Training adjusts WQ, WK, and WV so that the blends are the ones that help predict the next token.

Why the scores are divided by √dk

Softmax is sensitive to the size of its inputs. If one score is much larger than the others, nearly all the weight goes to it and the weights barely change when the scores move, so the gradients that training relies on become tiny. The paper's explanation is that dot products grow with vector length: if each component of q and k is random with mean 0 and variance 1, their dot product "has mean 0 and variance dk". Dividing by √dk brings the variance back to 1 regardless of dk. The authors present this as a suspicion that matches their observation that unscaled dot products did worse at large dk, not as a proof.

The mask turns attention into a next-token predictor

The minus-infinity trick in the worked example is what makes this a language model. In the paper's decoder, which GPT later adopted, each position may attend only to itself and earlier positions, implemented "by masking out (setting to −∞) all values in the input of the softmax which correspond to illegal connections." Because no position can see its own future, the model can be asked to predict the next token at every position of a training text at the same time. A 2,048-token passage gives 2,048 prediction exercises in one pass of matrix multiplications. When the trained model generates text, it still produces one token at a time, appending each to the input.

Heads, positions, and the rest of the layer

One attention step produces one set of weights per token, so it can follow only one pattern of relevance at a time. Multi-head attention runs several attention functions in parallel, each with its own WQ, WK, and WV projecting into a smaller space, then joins the results and multiplies by one more matrix. The original model used 8 heads of size 64; GPT-3 uses 96 heads of size 128. Because each head is smaller, the total cost is about the same as one big head.

Attention, as computed above, ignores word order: shuffle the rows of X and the outputs shuffle with them. The model therefore adds a positional encoding, a vector that depends on the position, to each token's embedding before the first layer. The original paper used fixed sine and cosine waves; learned position vectors worked about as well.

Attention is also only half of each layer. After it, every token's vector passes separately through a small two-layer network, the feed-forward sublayer, and each sublayer's input is added back to its output. A full model stacks many such layers: 6 in the original, 12 in the first GPT, 96 in GPT-3. Attention is the only place where tokens exchange information; the feed-forward sublayers process each token on its own.

Why it made models like ChatGPT possible

Before 2017, the standard language models were recurrent neural networks, such as LSTMs. They read tokens one at a time and carry a single state vector forward, computing each new state from the previous state and the current token. That design has two costs. Training cannot process the positions of a sequence in parallel, because step 100 needs the result of step 99. And for word 1 to influence word 500, its information has to pass through 499 updates, which makes long-range relationships hard to learn. The paper compares layer types on exactly these points:

Parallel work matters because the hardware used for training, graphics processors, is fast at large matrix multiplications and slow at long chains of small dependent steps. The paper notes that dot-product attention "can be implemented using highly optimized matrix multiplication code." OpenAI's first GPT, in 2018, took the masked half of this design for plain next-token prediction: "We trained a 12-layer decoder-only transformer with masked self-attention heads." Its authors chose it because it offered "a more structured memory for handling long-term dependencies in text" than recurrent networks. The same study found that a Transformer's error falls predictably as the model, the data, and the training compute grow, along straight lines on log-log plots over many orders of magnitude. Predictable gains made it rational to spend far more on one model.

GPT-3, in 2020, is the same mechanism made very large: 175 billion parameters, 96 layers, 96 attention heads per layer, a 2,048-token context, and 300 billion training tokens, spread across many GPUs "along both the depth and width dimension". It differs from the original only in details, such as alternating full attention with attention restricted to nearby tokens in some layers.

A large next-token predictor is still not a chat assistant. OpenAI states that "ChatGPT is fine-tuned from a model in the GPT-3.5 series" and trained "using Reinforcement Learning from Human Feedback (RLHF), using the same methods as InstructGPT". In that method, people write example answers and rank the model's outputs, a second model learns to predict those rankings, and the language model is then trained to produce outputs that score well. So the chain runs like this. Attention replaced step-by-step reading with parallel matrix multiplication and direct connections between all positions. That made training on huge amounts of text practical and let models use long contexts, and their error kept falling predictably with scale. That justified GPT-3-sized models. Human-feedback training then turned one of those models into ChatGPT.

Limits

Attention compares every token with every other, so its cost grows with the square of the context length: doubling the context quadruples that part of the work. That is one reason GPT-3 fixed its context at 2,048 tokens and restricted some layers to attend only to nearby tokens, a shortcut the original paper had already proposed for very long sequences.

The sources show that attention was the architecture these models used and that it trained in parallel, used long context better than recurrent networks, and improved smoothly with scale. None of them tests whether some other architecture could have produced a ChatGPT; the claim that attention "made it possible" means it was the practical route taken, not the only conceivable one. ChatGPT's own architecture has not been published, so its details are inferred from GPT-3 and InstructGPT.

Finally, the attention weights show where a head looked, not why the model produced its answer. The visualizations above are suggestive examples, and the authors present them with hedged language for that reason.
